# 미니어처 유닛 학습 도구

사진에서 여러 미니어처의 위치와 유닛 이름을 라벨링하고 YOLOv8n 객체 탐지 모델을 학습하는 Windows 데스크톱 프로그램입니다. 프로젝트와 학습 결과는 선택한 PC 폴더에 저장됩니다.

Python 3.10과 Python Launcher, Tcl/Tk가 필요합니다. `start.cmd`를 더블클릭하면 이 폴더의 `.venv`에 필요한 패키지를 설치하고 앱을 실행합니다. 첫 설치와 사전 학습 모델의 첫 다운로드에는 인터넷 연결이 필요합니다. 설치 파일은 수 GB의 디스크 공간을 사용합니다.

NVIDIA GPU를 사용하려면 `setup_gpu.cmd`를 한 번 실행한 뒤 `start.cmd`를 실행합니다. CUDA 12.1용 PyTorch를 설치하며 다운로드는 수 GB입니다. 설치 마지막에 `CUDA available: True`와 GPU 이름이 표시되는지 확인합니다. GPU를 사용할 수 없으면 학습 장치를 CPU로 선택할 수 있습니다. 환경은 이 프로그램의 `.venv`에 설치됩니다.

2026년 11월 17일 확인한 Wahapedia 11판의 팩션별 Army List를 바탕으로, `projects/wahapedia-11e/`에 24개 팩션 프로젝트와 1,403개 데이터시트 항목을 등록했습니다. Space Marines의 챕터 항목, 각 팩션 목록에 제시된 동맹 항목, Legends 357개를 포함합니다. Legends는 선택 목록에서 `[Legends]`로 표시합니다. 앱의 `프로젝트 열기`에서 이 폴더 아래 원하는 팩션 폴더를 선택합니다. [Wahapedia 11판](https://wahapedia.ru/wh40k11ed/the-rules/core-rules/)

공유 카탈로그는 `Assets/WarhammerAssistant/Units.json`입니다. 각 유닛의 이름, 팩션, 원문 URL과 `label`을 저장하며, 팩션 프로젝트의 클래스 이름과 내보내는 `labels.txt`는 이 `label`을 사용합니다. `Intercessor Squad`는 기존 `intercessor` 식별자를 사용합니다. 새 식별자는 `space_marines__terminator_squad`처럼 팩션과 데이터시트 경로를 조합합니다.

사진은 각 프로젝트에 추가합니다. 실제로 라벨링한 유닛부터 학습할 수 있고, 데이터셋의 클래스 ID는 학습 대상에 맞춰 연속 번호로 변환됩니다. 프로젝트의 기존 박스 ID는 유지되며 `manifest.json`의 `class_id_mapping`에 대응 관계가 기록됩니다. 시각 인식 모델을 학습하려면 실제 미니어처 사진과 위치 라벨이 필요합니다.

카탈로그에서 프로젝트를 다시 생성하거나 새 유닛을 반영하려면 이 폴더에서 아래 명령을 실행합니다. 기존 클래스 순서와 사진·라벨을 보존하고 누락된 유닛을 추가합니다. 이 명령은 로컬 `Units.json`을 읽습니다.

```powershell
.venv\Scripts\python.exe catalog.py
```

1. 새 프로젝트를 만들고 저장 폴더를 선택합니다. 이후에는 같은 폴더를 열어 작업을 이어갑니다.
2. 유닛 이름을 추가합니다. Unity에 연결할 이름은 유닛 카탈로그의 `label`과 맞춥니다. 예를 들어 `intercessor`를 사용할 수 있습니다. 이름을 추가한 순서가 프로젝트의 클래스 ID가 됩니다. 카탈로그 프로젝트에서는 선택 목록에 유닛 이름이 보이고, 아래 `Unity label` 필드에서 실제 식별자를 확인하거나 복사할 수 있습니다.
3. 사진을 불러옵니다. 앱이 회전 정보를 적용한 RGB 사본을 프로젝트 안에 저장합니다. 같은 내용의 사진은 중복으로 추가하지 않습니다.
4. 유닛 이름을 선택하고 사진 위에서 드래그해 각 미니어처를 감싸는 박스를 그립니다. 한 사진에 보이는 인식 대상마다 박스를 지정합니다. `선택 / 이동 / 크기` 모드에서는 박스를 이동하고 모서리를 드래그해 크기를 조절할 수 있습니다. 박스를 선택해 종류를 변경하거나 삭제할 수도 있습니다. 마우스 휠로 확대하고 스크롤바로 이동합니다.
5. 사진을 검토 완료로 저장합니다. 인식 대상이 없는 배경 사진은 박스 없이 검토 완료로 저장합니다. 검토하지 않은 사진은 학습에서 제외됩니다.
6. 학습·검증 분할을 정하고 학습을 시작합니다. 자동 분할은 같은 설정에서 재현됩니다. 같은 촬영 세션의 연속 사진이 양쪽에 섞이지 않도록 촬영 세션별로 학습 또는 검증을 직접 지정할 수도 있습니다. 완료한 사진에 실제 박스가 있는 유닛 종류가 학습 대상이며, 해당 유닛은 학습과 검증에 각각 포함되어야 합니다.
7. 학습 로그와 진행률을 확인합니다. 반복 횟수인 epoch, 입력 크기, batch, 학습 장치를 조절할 수 있습니다. GPU 메모리 부족 오류가 나면 batch 또는 입력 크기를 낮춰 새 학습을 시작합니다.
8. 학습이 끝나면 저장된 모델을 선택하고 새 사진으로 탐지를 시험합니다. 학습에 쓰지 않은 촬영 세션의 사진으로 잘못 찾거나 놓치는 유닛을 확인합니다.

학습을 시작할 때 검토한 사진과 라벨을 별도의 데이터셋으로 복사합니다. 실행 중인 학습은 이 사본을 사용합니다. 프로젝트의 이미지·라벨을 고쳐 다음 학습에 반영할 수 있습니다. `작업 중단`은 현재 epoch의 체크포인트가 저장된 뒤 학습을 종료합니다. `중단한 학습 이어하기`에서 해당 실행의 `weights/last.pt`를 선택하면 원래 데이터셋과 설정으로 남은 학습을 진행합니다. 최적 체크포인트는 `weights/best.pt`, 마지막 체크포인트는 `weights/last.pt`, epoch별 기록은 `results.csv`에 저장됩니다.

프로젝트 폴더에는 `project.json`과 관리하는 사진 사본이 저장됩니다. 프로젝트를 옮기거나 백업할 때 폴더 전체를 복사합니다. 사진·라벨 편집은 옮긴 폴더에서도 이어갈 수 있습니다. 중단된 학습을 이어할 때는 체크포인트가 기록한 원래 절대 경로의 데이터셋과 결과 폴더가 필요합니다. 같은 프로젝트를 여러 앱에서 수정하면 충돌 안내가 표시되므로 최신 프로젝트를 다시 엽니다.

Unity용 내보내기는 고정 크기의 `miniature_detector.onnx`, 클래스 순서대로 나열한 `labels.txt`, 입출력 설명인 `manifest.json`을 만듭니다. 모델은 `[1, 3, H, W]` RGB 입력과 0~1 값을 사용하며, 출력은 박스 `float[N, 4]`, 클래스 ID `int32[N]`, 점수 `float[N]` 순서입니다. 박스 좌표는 입력 픽셀 기준 `xMin, yMin, xMax, yMax`입니다. Unity의 **Warhammer Assistant > Import Training Export…**에서 파일 세 개가 있는 폴더를 선택합니다. 레이블은 공유 카탈로그의 `label`과 일치해야 합니다.

PC 미리보기와 Unity는 비율 유지 리사이즈와 패딩을 사용합니다. Unity는 출력 박스를 원본 영상으로 되돌리고 점수 필터링과 클래스별 NMS를 적용합니다. 내보내기는 ONNX 형식과 출력 구조를 검사합니다. Quest에서의 정확도와 실행 성능은 실제 기기 검증이 필요합니다.

실제 미니어처 사진을 준비하기 전에는 인식 정확도를 평가할 수 없습니다. 여러 방향, 거리, 도색, 조명과 가려짐을 포함해 사진을 모으고, 검증 사진은 별도의 촬영에서 확보합니다. 처음에는 구분할 유닛 몇 종류로 전체 흐름을 확인할 수 있습니다.

모델 학습은 Ultralytics 패키지와 해당 모델 가중치를 사용합니다. 프로젝트의 기존 모델과 별도의 라이선스가 적용되므로 배포 시 사용하는 버전의 조건을 확인합니다. [Ultralytics 라이선스](https://github.com/ultralytics/ultralytics/blob/main/LICENSE)

개발 확인은 이 폴더에서 `.venv\Scripts\python.exe -m pip install pytest` 후 `.venv\Scripts\python.exe -m pytest tests -q`로 실행할 수 있습니다. GUI 테스트에는 사용 가능한 데스크톱 세션이 필요합니다.
